## عن المشروع

REVORA MOTO تطبيق تجارة إلكترونية متخصص في الدراجات النارية ومستلزماتها. يجمع واجهة المتجر وحساب العميل ولوحة الإدارة في تطبيق واحد، ويستخدم Supabase للمصادقة وقاعدة البيانات والصلاحيات.

يدعم التطبيق العربية والإنجليزية، ويستخدم الجنيه المصري EGP بوصفه العملة التجارية الأساسية. تُنفذ العمليات الحساسة مثل إنشاء الطلب وحساب الخصم والتحقق من المخزون والدفعة المبدئية على الخادم أو داخل PostgreSQL، بدل الاعتماد على قيم يرسلها المتصفح.

## الميزات

### المتجر والتجارة

- تصفح المنتجات والدراجات الجديدة والمستعملة.
- البحث والتصفية والترتيب وعرض النتائج على صفحات.
- صفحات تفاصيل المنتجات والدراجات والصور والمواصفات والتوافق.
- مقارنة الدراجات وإدارة المفضلة ومرآب العميل.
- سلة تدعم الخيارات والكميات مع إعادة التحقق من السعر والمخزون.
- إتمام الطلب باستخدام بيانات العميل وعناوينه.
- إنشاء طلبات حجز للدراجات ومتابعة حالتها.

### حساب العميل

- الملف الشخصي وإدارة العناوين.
- سجل الطلبات وتفاصيلها والحجوزات.
- المفضلة والمرآب ومراجعات المنتجات.
- الإشعارات وطلبات الإرجاع وتسجيلات الضمان ومطالباته.

### إدارة المتجر

توجد صفحات إدارية للوحة المعلومات والمنتجات والخيارات والدراجات والطلبات والحجوزات والعملاء والمخزون والفروع والمستودعات والموردين وأوامر الشراء والعروض والمراجعات والإرجاع والضمان والموظفين والأدوار والصلاحيات والإعدادات والتقارير وسجل التدقيق.

تختلف درجة اكتمال بعض سير العمل الإداري. راجع [تقرير تدقيق التنفيذ](./IMPLEMENTATION_AUDIT.md) و[حالة الأنظمة](./AGENT_STATUS.md) لمعرفة ما تم التحقق منه وما يحتاج إلى استكمال.

## التشغيل المحلي

### المتطلبات

- Node.js 20.9 أو أحدث.
- npm.
- Supabase CLI.
- Docker أو Podman لتشغيل Supabase المحلي واختبارات قاعدة البيانات والمتصفح.

### خطوات التشغيل

1. نزّل المشروع وثبّت الاعتماديات:

   ```bash
   git clone https://github.com/AXE-Hex/REVORA-MOTO.git
   cd REVORA-MOTO
   npm ci
   ```

2. ابدأ خدمات Supabase المحلية:

   ```bash
   npx supabase start
   ```

3. انسخ `.env.example` إلى `.env.local`:

   ```bash
   cp .env.example .env.local
   ```

   خذ عنوان المشروع المحلي ومفتاحه العام من ناتج `npx supabase status`. اضبط القيم التالية للتطوير المحلي:

   ```dotenv
   NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321
   NEXT_PUBLIC_SUPABASE_ANON_KEY=المفتاح_العام_المحلي
   NEXT_PUBLIC_SITE_URL=http://localhost:3000
   ```

   لا تضع مفتاح `service_role` في متغير يبدأ بـ`NEXT_PUBLIC_` أو في كود المتصفح.

4. أعد إنشاء قاعدة البيانات **المحلية** من الترحيلات وبذرة التطوير:

   ```bash
   npx supabase db reset --local
   ```

   تنشئ `supabase/seed.sql` بيانات عرض تجريبية للتطوير المحلي. لا تستخدمها في مشروع سحابي أو إنتاجي.

5. شغّل التطبيق:

   ```bash
   npm run dev
   ```

6. افتح الواجهة:

   - العربية: [http://localhost:3000/ar](http://localhost:3000/ar)
   - الإنجليزية: [http://localhost:3000/en](http://localhost:3000/en)

## متغيرات البيئة

يحتوي `.env.example` على أسماء المتغيرات المعتمدة في المشروع. أضف القيم اللازمة إلى `.env.local` محليًا أو إلى إعدادات بيئة الاستضافة.

| المتغير                         | الغرض                                         |
| ------------------------------- | --------------------------------------------- |
| `NEXT_PUBLIC_SUPABASE_URL`      | عنوان Supabase الذي يتصل به التطبيق.          |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | المفتاح العام؛ صلاحياته مقيدة بسياسات RLS.    |
| `NEXT_PUBLIC_SITE_URL`          | العنوان الأساسي للروابط والبيانات المنظمة.    |
| `PAYMENT_PROVIDER`              | مزود الدفع الحالي؛ الوضع الافتراضي `sandbox`. |
| `PAYMENT_GATEWAY_URL`           | عنوان بدء الدفع عند تنفيذ تكامل المزود.       |
| `PAYMENT_GATEWAY_REFUND_URL`    | عنوان تنفيذ الاسترداد عند توفر تكامل المزود.  |
| `PAYMENT_GATEWAY_SECRET`        | بيانات سرية خادمية لتكامل بوابة الدفع.        |
| `PAYMENT_WEBHOOK_SECRET`        | التحقق من توقيع إشعارات الدفع والاسترداد.     |
| `REVORA_TASK_SECRET`            | حماية نقاط المهام المجدولة.                   |
| `SUPABASE_SERVICE_ROLE_KEY`     | مفتاح خدمة عالي الصلاحيات؛ خادمي فقط.         |
| `USD_EGP_RATE`                  | سعر تحويل موجب وحديث عند تفعيل عرض الدولار.   |

**لا** تضع `SUPABASE_SERVICE_ROLE_KEY` أو أسرار الدفع في متغيرات `NEXT_PUBLIC_*` أو في ملفات Git أو كود المتصفح.

## قاعدة البيانات والترحيلات

توجد مخططات PostgreSQL في `supabase/migrations/`. وتشمل مجالات الحسابات والكتالوج والخيارات والتوافق والدراجات والسلة والطلبات والحجوزات والمدفوعات والمخزون والموردين والعروض والإرجاع والضمان والإشعارات والتقارير.

- أضف تغييرات المخطط كترحيلات جديدة متتابعة.
- لا تعدّل ترحيلًا سبق تطبيقه؛ أصلح المخطط بترحيل أمامي جديد.
- اختبر الترحيل محليًا وشغّل اختبارات SQL/RLS.
- لا تستخدم `supabase db reset --linked`.
- لا تدفع بيانات `supabase/seed.sql` أو بيانات الاختبار إلى السحابة.
- راجع الترحيل قبل تطبيقه على مشروع سحابي.

## الأمان والخصوصية

- تتحقق الصفحات والإجراءات الخادمية من جلسة المستخدم.
- تضبط RLS الوصول إلى البيانات بحسب المستخدم والصلاحيات.
- تتحقق قواعد الخادم وقاعدة البيانات من الملكية والأدوار في الإجراءات الحساسة.
- تحسب قاعدة البيانات أسعار الطلب والخصومات والتحقق من المخزون والدفعات المبدئية.
- تفصل البيانات العامة عن البيانات التشغيلية مثل معلومات الموردين وتكاليف الشراء.
- تحفظ الأسرار في إعدادات الخادم فقط، وتبقى بيانات البذرة للتطوير المحلي.

هذه الضوابط لا تعني أن مراجعة الأمان أو اعتماد الإنتاج اكتمل. راجع [سياسة الأمان](./SECURITY.md) و[إعداد Supabase](./CLOUD_SETUP.md) و[تدقيق التنفيذ](./IMPLEMENTATION_AUDIT.md).

## الدفع والإشعارات البريدية

يوفر المشروع بنية مستقلة عن مزود الدفع وسجلات للدفعات والأحداث والتحقق من إشعارات الويب ومنع التكرار. الإعداد الافتراضي تجريبي؛ لم يتم اختيار مزود دفع مصري أو ربط بيانات اعتماده. لذلك لا تعتبر حالة الدفع المعلقة تحصيلًا ناجحًا، ولا يتوفر حاليًا تحصيل فعلي لبطاقات Visa/Mastercard أو InstaPay أو تنفيذ استرداد فعلي.

يحتفظ التطبيق بصندوق لإشعارات البريد، لكن إرسال الرسائل للعملاء يحتاج إلى مزود بريد وإعداد النطاق والمفاتيح. التفاصيل في [وثائق الدفع والاسترداد](./PAYMENTS.md).
